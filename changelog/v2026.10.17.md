## v2026.10.17

### btclib requires the siblings' releases of 2026-10-17

The floors are btclib-ecc 2026.10.17, btclib-secp256k1 0.8.0.12 and
bitcoin-core-rpc 2026.10.17. SECURITY.md cites btclib-ecc 2026.10.17's line
for the key copy in `dsa.Signer` (closes #2702).

### `PartialMerkleTree.serialize` checks the transaction count

With `check_validity=False`, it refuses a non-int as `BTClibTypeError` and an
int that four octets do not hold as `BTClibValueError`, and so does
`MerkleBlock.serialize` (closes #2668).

### CI

`verified-signatures.yml` checks that every commit pushed to `main` is verified
(issue btclib-org/.github#1738, closes #2694). The pyroma hook builds nothing
from source (issue btclib-org/.github#1763, closes #2685).

### Documents

RELEASING.md checks every btclib-org dependency (closes #2683). The bypass is
for emergencies (issue btclib-org/.github#1740). A report easy to rediscover is
fixed as soon as possible (issue btclib-org/.github#1771).
